# Доказательный план GEO: подготовленные изменения

## Реализовано

- План действий: три первых задачи, остальные раскрываются отдельно.
- У каждой задачи: основание, исполнитель, условия выполнения и повторная проверка.
- Источники привязаны к вопросам, моделям, исходным ответам и URL.
- Убраны фиксированные обещания прироста баллов и безусловное заполнение плана десятью советами.
- Собственный домен не предлагается как независимая редакционная площадка.
- Ошибки провайдеров и пустые ответы исключены из анализа отсутствия бренда.
- Разбор источников разделён по провайдеру и модели, с явными числителями и знаменателями.
- Аудит сайта доступен прямо в плане действий. Его баллы отделены от видимости бренда.
- Новые материалы из сканирования источников и Telegram-поиска создают уведомления владельцу кабинета со ссылками. Первичная загрузка формирует базу без уведомлений; повторное обнаружение той же публикации не создаёт новое уведомление.
- API выбранных моделей больше не подписывается как пользовательская Алиса.

## Границы результата

Разбор источников описывает одно исследование. Он не раскрывает закрытый алгоритм Алисы и не является обученной причинной моделью. Существующие механизмы накопления наблюдений и экспериментов сохранены; новая статистика не заменяет их.

Редакционный доступ, актуальность и авторитетность площадки требуют проверки. Указанная моделью ссылка подтверждает наличие ссылки в ответе, но не достоверность содержимого страницы.

Уведомления реализованы внутри кабинета, не как email или Telegram-рассылка. Фактический регулярный сбор требует работающего worker и подключённых источников.

## Проверки

- 70 тестов: source_evidence, research_intelligence, competitor_intelligence, geo_site_audit, first_real_product, publication_learning, alice_learning.
- Для изолированного запуска общему startup приложения нужна отдельная SQLite-база с созданными таблицами и тестовый PROVIDER_SECRET_KEY длиной не менее 32 символов. Production-секреты не используются.
- Frontend: production build и Playwright evidence-plan.spec.ts пройдены.
- Ruff для изменённых Python-файлов и git diff --check пройдены.
- Сохраняется предупреждение Vite о размере основного JS-бандла больше 500 kB.

## Выпуск

Миграций базы в этом наборе изменений нет. До обновления сервер должен иметь проверенную резервную копию, сохранённый предыдущий commit и Docker-образы для отката. Не запускать обновление поверх неизвестных серверных изменений.

Проверить git status на /opt/ai-ranking-os, получить этот commit, собрать backend/frontend штатным deployment/production/scripts/deploy.sh. После обновления проверить /ready, контейнер worker и авторизованный сценарий «План действий → основание совета → аудит сайта → уведомления».

Проверено после выкладки: публичный HTTPS /ready; авторизованный вход; отчёт #64 с новым source_analysis; backend, worker, frontend, nginx имеют статус healthy и 0 перезапусков. В Docker-контекст больше не попадают вложенные .env и резервные копии; отсутствие этих файлов проверено внутри нового образа. Ограничение проверки мониторинга: worker начал записывать результаты обхода, но Telegram-источники возвращают Network is unreachable, VK требует API-токен, у YouTube-источника не определён channel ID. Успешный регулярный сбор всех источников и доставка реального нового материала пока не подтверждены. Это отдельные задачи подключения, не исправленный crash loop.
