# Первый клиент: тестовый запуск

Этот сценарий предназначен для ручного пилота без автоматического списания денег.
Каждый клиент получает отдельное приглашение и отдельный кабинет.

## Подготовка

1. Администратор открывает «Управление платформой → Клиенты».
2. Нажимает «Создать приглашение», указывает email клиента и срок действия 72 часа.
3. Передаёт клиенту одноразовую ссылку. Ссылка не публикуется в общем чате и не
   сохраняется в отчёте.
4. Клиент открывает ссылку, задаёт имя и пароль, затем входит по email и паролю.

Приглашение — это доступ к закрытому бета-тесту, а не платная подписка. Лимиты
пилота настраиваются администратором отдельно и пока не являются биллингом.

## Проверка ценности за один сеанс

Клиент нажимает три действия:

1. «Новое исследование»: название компании, главный сайт, отрасль и регион.
2. «Проверить запросы»: система показывает частотные запросы Wordstat, их можно
   удалить или дописать перед запуском проверки в Алисе/YandexGPT.
3. «Запустить анализ»: после завершения открывается отчёт с итоговой оценкой,
   тремя приоритетными действиями, запросами, ответами моделей, конкурентами и
   источниками с URL.

Повторная проверка создаёт новый снимок. Сравнение выполняется только внутри
этого кабинета; ссылки на чужой research ID должны возвращать 404.

## Что считать успешным пилотом

- клиент сам входит по приглашению;
- исследование завершается и отчёт открывается;
- в отчёте есть понятные доказательства: запрос, модель, ответ, URL и дата;
- второй тестовый клиент не видит первый отчёт, экспорт или список его данных;
- администратор видит лимиты, статус и историю изменений клиента.

## Ограничения первого пилота

- автоматическая оплата и тарифы не включены;
- реальные запросы Wordstat и Webmaster требуют действующих ключей/подтверждённого
  сайта клиента;
- рекомендации являются измерительным отчётом по сохранённой выборке, а не
  гарантией попадания в ответ Алисы;
- ежедневный мониторинг конкурентов включается отдельно после первого успешного
  исследования.
